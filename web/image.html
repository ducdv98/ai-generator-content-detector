Image Watermark Lab

Three ways an image gets marked as AI-made, what each one looks like as evidence, and which survive being shared.

What this page can and cannot show. It reads file labels (including signed Content Credentials), Stable Diffusion's public pixel watermark, and a keyed watermark made here. It cannot read the learned watermarks vendors use today, such as Google's SynthID on Gemini and OpenAI images: their detectors are neural networks that are not published. Google and OpenAI each run a public checking tool for their own images.

How the marks work

File labels. An image file holds the picture plus blocks of notes. C2PA Content Credentials are a signed note saying who made the image and how; IPTC DigitalSourceType is a plain unsigned tag. Both are exact and easy to read, and both are gone the moment a platform, a chat app or a screenshot copies only the picture.

Public pixel watermark. Stable Diffusion's scripts nudge one value in every 8×8-pixel block of a colour channel onto a grid, spelling a fixed message over and over. No key: anyone can read it, and anyone can remove or forge it. It breaks when the pixel grid shifts (resize, crop) or values are re-rounded (JPEG).

Keyed pixel watermark. A key generates a faint noise pattern that is added to the brightness. Only the key regenerates the pattern, so only its holder can detect it, and it survives compression and resizing because the evidence is spread over thousands of values. This one is a simple hand-built version of the idea.

Learned watermarks (not runnable here). SynthID, Adobe's TrustMark and Meta's watermarks replace the hand-built pattern with a trained encoder network that writes the mark and a decoder network that reads it, trained together against crops, rotations, filters and compression. Same principle as the keyed mark; the secret is the network's weights. More detail and sources: docs/image-watermarking.md.
